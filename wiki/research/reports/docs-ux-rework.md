# Docs-UX rework — the plan

> Supersedes the earlier (ts-morph) draft of this file. Direction set with the maintainer
> 2026-06-07; the risky seam was proven by a worktree spike (below). Short by design.

## Principle

The docs exist to help a user **use** the API: find a signature, the **actual options**, an
interface's **methods + how to call each**, with **links that always resolve**. Stop
hand-rolling what a standard tool gives for free.

## The architecture

**Split generated from authored:**

1. **API reference = TypeDoc.** Reads `src/index.ts` + our TSDoc, produces **member-level**
   docs natively — functions with parameters + expanded options, option types
   (`GenerateOptions`/`WorldOptions`) with every field, interfaces (`World`/`Registry`) with
   every method, all cross-linked. **Delete** the bespoke pipeline: `scripts/docs/extract.ts`,
   `scripts/docs/curation.ts`, `scripts/docs-generate.ts`, `site/src/lib/docs/api/manifest.generated.ts`,
   `ParameterTable.svelte`, `SignatureBlock.svelte`, and the custom `/docs/api` renderer +
   the `docs:generate`/`docs:check` parity machinery. TypeDoc + TSDoc replace all of it.

2. **Code samples = Shiki + Twoslash.** Highlighted, **type-checked at build** (an invalid
   sample — undefined `UserSchema`, missing import, bad option — is a build error: the forcing
   function for the quality the maintainer wants), with **clickable type tokens that link into
   the API reference**. Slots into the site's existing Shiki call as a transformer.

3. **Guides (Getting Started, Concepts, …) = hand-written prose**, rewritten: lead with one
   complete, self-contained, twoslash'd `generate` example (imports + schema shown) → then
   **variations, not steps** ("another way to do it": seeded world = the options primer,
   matchers, relations) → concise. No `SpeedClaim` boast, no "zod v4 not v3" noise.

## Spike result (the load-bearing proof)

The **clickable-type → TypeDoc-anchor seam WORKS** (proven against the real API):
- Join key = **declaration location** (`file:line`), not token text — so two `seed` tokens
  correctly resolve to `GenerateOptions.seed` vs `WorldOptions.seed`.
- Twoslash gives per-token offsets → a TS language service gives `getDefinitionAtPosition` →
  TypeDoc JSON's `sources.{fileName,line}` is the index → URL derived from `kind`+`name`. ~60
  lines; ~1–2 days to productionize. Zero dead links in the prototype.
- **One gotcha:** the language service and TypeDoc must agree on **src vs dist** — map
  `zod4-mock` → `src/index.ts` via `paths` (the site's tsconfig already does this), or point
  TypeDoc at `dist`. Without it the join silently yields 0 links.
- TypeDoc runs clean on the real lib (TS 6.0.3, ESM, Zod v4 internals, workspace dep): 0 errors;
  member-level confirmed (GenerateOptions 12 fields, WorldOptions 7, Registry 6 methods).
- Build cost: TypeDoc ~1.8s once; twoslash ~0.24s/sample (warm program cuts it). Build-time
  only, zero runtime.

**Recommended integration: render TypeDoc JSON in our site** (keeps the `@dxlbnl/ui` look +
Pagefind search + the twoslash type-links), with TypeDoc HTML emitted as the stable link
target. Fallback if minimizing work wins: serve **TypeDoc's own HTML** at `/docs/api` (its
theme, but member-level and correct) — links resolve to it directly.

## New deps (dev/build-time only, D13-exempt)

`typedoc`, `@shikijs/twoslash`, `twoslash` (+ `typedoc-plugin-markdown` only if we render via
markdown). `shiki` is already a site dep. → New rule: the API reference is generated by
TypeDoc, code samples are type-checked by Twoslash; both build-time.

## Content gap to close (not tooling)

`GenerateOptions`/`WorldOptions` option fields lack per-field TSDoc → their descriptions render
empty. Add one-line TSDoc per field in `src/types.ts` as part of the rewrite.
