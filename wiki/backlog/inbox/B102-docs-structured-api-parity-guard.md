## Description

Third implementation card of B94's docs system. Builds the structured API
reference view and the `docs/api-reference.md` parity guard, then rewrites
D5 to point at the new entry point.

### Scope

- **`site/src/lib/docs/api/manifest.ts`** — typed `ApiManifest` constant:
  `ReadonlyArray<ApiSymbol>` where each entry has `name`, `kind`,
  `signature`, `description`, `examples`, `since`, `seeAlso`. Covers the
  ~25 symbols in `docs/api-reference.md`'s "Exports overview" table. A
  thin TS assertion at the file bottom type-checks the manifest against
  the actual library exports — when a public symbol changes signature,
  the manifest stops type-checking until the author updates it.

- **`site/src/routes/docs/api/+page.svelte`** — rebuild as a typed-driven
  structured view: per-symbol `<SignatureBlock>` cards, right-rail TOC
  auto-generated from the manifest, `<ParameterTable>` for parameterised
  symbols.

- **`scripts/docs-generate.ts`** — reads `manifest.ts`, emits
  `docs/api-reference.md` from a template. Idempotent, no flags
  (regenerate from scratch). Run via `tsx` or compiled.

- **`pnpm docs:generate`** — root script, runs the generator.
- **`pnpm docs:check`** — runs `docs-generate --check` (no-write); fails
  if on-disk `docs/api-reference.md` doesn't match the manifest. Wired
  into `pnpm validate`.

- **D5 rewrite**:
  - `wiki/decisions.md`: append/amend an ADR for D5 explaining the
    manifest-as-entry-point shift.
  - `wiki/architecture.md` Rules: replace the existing D5 rule with
    > When a public API changes,
    > `site/src/lib/docs/api/manifest.ts` **MUST** be updated in the
    > same step; `docs/api-reference.md` is regenerated by
    > `pnpm docs:generate` and parity is verified by `pnpm docs:check`.
    > (→ D5)
  - `CLAUDE.md` — sync the doc rule to match.

- **First commit of regenerated artifact**: running `pnpm docs:generate`
  produces the new canonical shape of `docs/api-reference.md`; commit
  that as the new baseline.

## Acceptance

- `/docs/api` renders as a structured per-symbol view.
- `pnpm docs:generate` is idempotent; running it twice produces no diff.
- `pnpm docs:check` passes in CI.
- Negative test: introduce a manifest change without regenerating;
  `pnpm docs:check` fails with a useful diff.
- D5 rule + ADR + CLAUDE.md doc-rule line updated.
- `pnpm validate` + `pnpm site:check` green.
