zod4-mock design system

A tight, dark-primary playground vocabulary. Token-driven, component-scoped, theme-flippable.

v1.0 last updated · today

Principles

Five rules that the components and tokens enforce. Read these first; they decide every trade-off below.

1 · Density over decoration

Power users want lots on screen. Row height is 28px, padding 4–8, type 11–13. No drop shadows on inline elements; no avatars; no decorative iconography.

2 · One accent, used sparingly

Zod purple appears only on: active subject, focused row, focused tab, primary CTA, the open + mod menu, and syntax keywords. Everything else is neutral.

3 · Tokens are the only source of truth

Every value (color, space, radius, type) lives in tokens.css as a CSS custom property. Components never hard-code. The light theme is one block of overrides.

4 · Mono for data, sans for UI

JetBrains Mono for: keys, types, modifiers, code, JSON, file names, kbd hints, counts. Inter for: button text, headings, titles, descriptive copy.

5 · Inline editing wins

Property keys, modifier values, file names — all editable in place. Modifiers are removable on hover. The + mod pill opens a search menu directly under the row, never a dialog.

Typography

Two typefaces. Inter is for UI chrome; JetBrains Mono is for everything that represents code or data. Never mix them within the same word.

Rules

  • Mono = anything that is code or could be typed: keys, types, modifier names, modifier values, JSON, file names, kbd hints, counts, version strings.
  • Sans = chrome that describes UI: section labels, button labels, body copy, headings.
  • Never use mono for paragraph text; never use sans inside a code block.
  • Numbers shown in tables or status bars use font-variant-numeric: tabular-nums.

Movement is purely functional — never decorative. Hover/active states are instant. The only animated transitions are: accordion chevron rotation, sheet fade-in, and tab-underline slide.

Buttons

Three variants. All 26px tall. Primary uses --accent-dim, default uses --bg-2, ghost is transparent. Icons are 12–13px and always Lucide-style.

Variants.btn / .btn.primary / .btn.ghost

Props

Prop Type Default Note
variant "default" | "primary" | "ghost" "default" primary for the page's single most important action
leadingIcon node — 12 or 13px Icon
disabled boolean false opacity 0.5, cursor not-allowed

Rules

  • Only one .primary per pane region. Top bar's "Export" is the global primary.
  • Use .ghost for icon-only top-bar actions (refresh, theme toggle).
  • Never put .primary inside a row or pill — primary is always full-button-sized.

Behavior

  • Items grouped by category; the search filters across all categories.
  • The scope chip shows which Zod base type the menu's options apply to.

Implementation notes for Claude Code

Read this before opening a PR. These are the conventions baked into the design — breaking them will make the system feel inconsistent.

1. Theme

  • Theme is controlled by html.light class on <html>. No data-theme attribute, no React context — just toggle the class.
  • Persist user choice in localStorage["theme"]. Restore on page load before React mounts to prevent flash.

2. Tokens

  • Components never reference hex colors directly. Always var(--token-name).
  • Adding a new color? Add it to tokens.css in both :root and html.light.
  • One-off colors are a smell. If you need a new color, name it.

3. Component conventions

  • One component per file. Each file: small JSX module + paired CSS file.
  • Component name = file name in PascalCase (row.jsx → Row).
  • State lives close to the leaves; the top-level App only holds cross-cutting state (theme, modal-open, selected-subject).
  • Use plain props; avoid context unless 3+ levels of prop-drilling are involved.

4. Accessibility

  • Selected items use aria-selected="true"; pressed seg buttons use aria-pressed.
  • All interactive elements have a focus ring: outline: 0; box-shadow: 0 0 0 2px var(--accent-soft).
  • Modal sheets trap focus; esc closes them.

5. Forbidden things

  • No drop shadows on inline elements. Shadows only on .float-menu and .export-sheet.
  • No emoji in product UI.
  • No gradients except the brand-logo square.
  • No animation on hover. Hover is instantaneous.
  • No icon without a paired label, except in the top bar's icon-only ghost buttons (which carry tooltips).

6. Spacing in JSX

Prefer flex/grid with gap over margin. Match the 4 / 6 / 8 / 12 / 16 / 24 scale; don't invent new values.
